# TikWeather

Мобильный сайт погоды с навигацией по дням и часам через TikiTaki.
Основан на оформлении и правилах AvaWeather.

Реализованы каркас приложения, модель сетки и навигация через TikiTaki.
Стартовая страница показывает индикатор загрузки в текущей ячейке.
Геолокация, погодные API и настоящие карточки входят в следующие этапы.

## Разработка

Нужен Node.js 24.15 или более новая версия ветки 24.

```sh
npm ci
npm run dev
```

Приложение открывается по адресу `http://localhost:5173/TikWeather/`.

```sh
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chrome
npm run test:e2e
```

`npm run check` запускает все проверки, включая production сборку и Playwright.
Для браузерных тестов используется Google Chrome.
Для среды с ограничением запуска дочерних процессов предусмотрена команда
`npm run test:e2e:connected`, которая выполняет общие сценарии через уже запущенный
Chrome с отладочным подключением. Настройка описана в документации тестирования.

## Стек

Vue 3 с Composition API и шаблонами, Pinia, строгий TypeScript, Vite,
Bootstrap 6.0.0 alpha.1, Vitest, Vue Test Utils, Playwright, ESLint и Prettier.
TikiTaki и Vue адаптер установлены из npm с зафиксированными версиями.

## Структура

Код организован по FSD. Правила зависимостей слоёв проверяются ESLint.
Все тесты находятся в `src/tests` и повторяют структуру исходного кода.

```text
src/
  app/                         Инициализация и глобальные стили
  pages/weather/               Страница погоды
  widgets/weather-grid/        Свайпы и жизненный цикл ячеек
  entities/weather/            Модель сетки и Pinia
  shared/locales/               Русские и английские строки
  shared/themes/                Начальные нейтральные цвета AvaWeather
  shared/ui/                   Общие элементы интерфейса
  tests/
    entities/weather/model/    Тесты сетки и хранилища
    pages/weather/ui/          Компонентные тесты страницы
    pages/weather/             Браузерные тесты страницы
    widgets/weather-grid/      Компонентные и браузерные тесты свайпов
    shared/lib/                Окружение браузера для компонентных тестов
```

Слой `features` появится вместе с соответствующими возможностями.

## Сетка

Первая ячейка первой строки всегда представляет текущую погоду.
Первая ячейка каждой следующей строки представляет сводку доступного дня.
Справа размещаются доступные часы соответствующего местного дня.

Сегодня отсчёт двухчасовых интервалов начинается с местного часа открытия
приложения с округлением вниз до целого часа. Например, при открытии в 10:30
следующие слоты будут 12:00, 14:00 и 16:00.
Будущие строки отсчитывают интервалы от полуночи и начинаются со сводки дня,
далее идут 02:00, 04:00 и следующие доступные часы.

Модель принимает реальные временные метки в миллисекундах Unix и часовой пояс IANA.
Она не создаёт отсутствующие дни или прогнозы и не ограничивает горизонт тремя днями.
Для источника с трёхчасовой детализацией предусмотрен отдельный интервал.
Две повторившиеся местные отметки времени при переводе часов имеют разные идентификаторы.
Получение погодных данных отделено от описания ячеек, поэтому обновление данных
не требует изменения идентификаторов уже доступных ячеек.

## Навигация

Свайп влево открывает следующий час, вправо возвращает предыдущий.
Свайп вверх открывает следующий день, вниз возвращает предыдущий.
При переходе между днями открывается первая ячейка выбранной строки.
Навигация останавливается на границах доступного прогноза.

После фокусировки области прогноза доступны стрелки клавиатуры.
Настройка уменьшения движения отключает анимацию перехода.
Движок держит текущую ячейку и до четырёх соседних. Содержимое создаётся
шаблонами Vue через опубликованный адаптер и `Teleport`, сохраняя Pinia и контекст Vue.
Обновление сетки сохраняет выбранную ячейку по её идентификатору, если она ещё доступна.
При закрытии экрана освобождаются обработчики и наблюдатели движка.

Браузерная страница с проверочными ячейками собирается отдельно в `dist-e2e`
и не попадает на GitHub Pages. Настоящие дни появятся после подключения API.

## GitHub Pages

Workflow `.github/workflows/ci.yml` проверяет форматирование, lint, типы, модульные
и компонентные тесты, собирает сайт и проверяет production сборку в Chrome.
После успешных проверок основной ветки сайт публикуется на
[GitHub Pages](https://gagarinbefree.github.io/TikWeather/).
Источником Pages настроен GitHub Actions.
Новый коммит отменяет предыдущий запуск для той же ветки.
Файл `.npmrc` закрепляет установку peer зависимостей Bootstrap при `npm ci`.
