# TikWeather

Мобильный сайт погоды с навигацией по дням и часам через TikiTaki.
Основан на оформлении и правилах AvaWeather.

Реализованы навигация через TikiTaki, определение местоположения,
карточка текущей погоды и фоновый прогноз. Текущая погода и первые дни
запрашиваются по порядку: WeatherAPI, Open Meteo, OpenWeatherMap. Для более
длинного прогноза приложение выбирает самый длинный доступный ответ.

## Разработка

Нужен Node.js 24.15 или более новая версия ветки 24.

```sh
npm ci
npm run dev
```

Приложение открывается по адресу `http://localhost:5173/TikWeather/`.

Для настоящей погоды скопируйте `.env.example` в `.env.local`, заполните
`VITE_WEATHER_API_KEY` и `VITE_OPENWEATHERMAP_API_KEY` соответствующими ключами
и перезапустите Vite. Open Meteo работает без ключа.
Для публикации добавьте `WEATHER_API_KEY` и `OPENWEATHERMAP_API_KEY` в секреты
GitHub Actions репозитория `gagarinbefree/TikWeather`. Workflow передаёт их сборке
как переменные Vite.
Секреты другого репозитория автоматически не наследуются.

Сайт статический, поэтому ключ в браузерной сборке доступен посетителю.
Файлы `.env.local` не сохраняются в Git. Тесты используют проверочные ключи
и перехватывают запросы, не расходуя лимиты настоящих сервисов.

```sh
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chrome
npm run test:e2e
```

`npm run check` запускает все проверки, включая production сборку и Playwright.
Для браузерных тестов используется Google Chrome.
Для среды с ограничением запуска дочерних процессов предусмотрена команда
`npm run test:e2e:connected`, которая выполняет общие сценарии через уже запущенный
Chrome с отладочным подключением. Настройка описана в документации тестирования.

## Стек

Vue 3 с Composition API и шаблонами, Pinia, строгий TypeScript, Vite,
Bootstrap 6.0.0 alpha.1, Vitest, Vue Test Utils, Playwright, ESLint и Prettier.
TikiTaki и Vue адаптер установлены из npm с зафиксированными версиями.

## Структура

Код организован по FSD. Правила зависимостей слоёв проверяются ESLint.
Все тесты находятся в `src/tests` и повторяют структуру исходного кода.

```text
src/
  app/                         Инициализация и глобальные стили
  pages/weather/               Страница погоды
  widgets/weather-grid/        Свайпы и жизненный цикл ячеек
  features/current-weather/    Загрузка, отмена и повтор текущей погоды
  features/forecast/           Фоновая загрузка и приоритет выбранного дня
  entities/weather/            Модель сетки и Pinia
  entities/location/           Геопозиция устройства и GeoJS
  shared/api/                  Ограничение запросов и проверка данных
  shared/locales/               Русские и английские строки
  shared/themes/                Именованная палитра AvaWeather
  shared/ui/                   Общие элементы интерфейса
  tests/
    entities/weather/model/    Тесты сетки и хранилища
    pages/weather/ui/          Компонентные тесты страницы
    pages/weather/             Браузерные тесты страницы
    widgets/weather-grid/      Компонентные и браузерные тесты свайпов
    shared/lib/                Окружение браузера для компонентных тестов
```

Погодные SVG, четыре начертания Inter, иконка приложения и палитра AvaWeather
находятся в `shared/assets` и `shared/themes/default.json`. Текущая погода и
прогноз получают разные пастельные поверхности по погодному условию из общей темы.
Тексты карточек и единицы измерения берутся из русских и английских ресурсов.

## Текущая погода

При открытии сайт запрашивает геопозицию устройства. Отказ, отсутствие API
или ожидание дольше 8 секунд переключают определение на GeoJS с лимитом 6 секунд.
Если GeoJS тоже недоступен, WeatherAPI получает запрос `auto:ip`.
Город по умолчанию не задан. Для координат устройства отдельный запрос к GeoJS не нужен.

После определения позиции сразу выполняется `current.json` с лимитом 15 секунд,
без ожидания почасового или дневного прогноза. Пока данных нет, в A1 показан
спиннер Bootstrap. Ошибка содержит отдельную кнопку повтора под сообщением слева.
Повтор и закрытие экрана отменяют предыдущий запрос и исключают устаревшие ответы.

Карточка показывает текущие измерения и время наблюдения в часовом поясе места.
Русский или английский язык выбирается по стране согласно правилам AvaWeather;
до определения страны используется язык браузера. Описания погоды, подписи,
направления ветра, единицы и ошибки хранятся в ресурсах. Названия городов выводятся
так, как возвращает доступный источник или GeoJS. При геолокации устройства и ответе
Open Meteo вместо названия показываются координаты.

## Сетка

Первая ячейка первой строки всегда представляет текущую погоду.
Первая ячейка каждой следующей строки представляет сводку доступного дня.
Справа размещаются доступные часы соответствующего местного дня.

Сегодня отсчёт двухчасовых интервалов начинается с местного часа открытия
приложения с округлением вниз до целого часа. Например, при открытии в 10:30
следующие слоты будут 12:00, 14:00 и 16:00.
Будущие строки отсчитывают интервалы от полуночи и начинаются со сводки дня,
далее идут 02:00, 04:00 и следующие доступные часы.

Модель принимает реальные временные метки в миллисекундах Unix и часовой пояс IANA.
Она не создаёт прогноз из отсутствующих погодных данных и не ограничивает горизонт тремя днями.
Отдельный планировщик создаёт пустые ячейки максимум для 16 дней. После ответа
источников число строк сокращается до фактически полученного количества дней.
При ответе OpenWeatherMap вместо двухчасовых слотов используются реальные отметки
его трёхчасового прогноза. Ближайшая будущая точка сегодняшнего дня доступна,
даже если до неё осталось меньше трёх часов. После смены поставщика часы сетки
обновляются вместе с загруженным прогнозом.
Две повторившиеся местные отметки времени при переводе часов имеют разные идентификаторы.
Получение погодных данных отделено от описания ячеек, поэтому обновление данных
не требует изменения идентификаторов уже доступных ячеек.

## Прогноз

Сразу после показа A1 приложение создаёт пустые ячейки максимум для 16 дней.
Пока прогноз ячейки не получен, в её центре показывается спиннер Bootstrap.
Загрузка идёт в фоне: сначала один день, затем три и затем полный доступный
горизонт. При переходе к ещё не загруженному дню меньший запрос отменяется,
и приложение сразу запрашивает нужный горизонт. Для длинного прогноза проверяются
Open Meteo, WeatherAPI и OpenWeatherMap; из успешных ответов выбирается самый
длинный. Поэтому число доступных дней зависит от ответивших сервисов и тарифа.
Уже загруженные дни сохраняются при ошибке; для неудавшегося запроса есть кнопка повтора.

Дневные и почасовые карточки используют иконки, пастельные цвета и локализованные
подписи из тех же ресурсов, что карточка текущей погоды. Временные метки прогноза
показываются в часовом поясе местоположения. В бесплатном трёхчасовом прогнозе
OpenWeatherMap нет УФ индекса и времени восхода и заката будущих дней; карточки
показывают «Нет данных» вместо вымышленных значений.

## Навигация

Свайп влево открывает следующий час, вправо возвращает предыдущий.
Свайп вверх открывает следующий день, вниз возвращает предыдущий.
При переходе между днями открывается первая ячейка выбранной строки.
Навигация останавливается на границах доступного прогноза.

После фокусировки области прогноза доступны стрелки клавиатуры.
Настройка уменьшения движения отключает анимацию перехода.
Движок держит текущую ячейку и до четырёх соседних. Содержимое создаётся
шаблонами Vue через опубликованный адаптер и `Teleport`, сохраняя Pinia и контекст Vue.
Обновление сетки сохраняет выбранную ячейку по её идентификатору, если она ещё доступна.
При закрытии экрана освобождаются обработчики и наблюдатели движка.

Браузерная страница с проверочными ячейками собирается отдельно в `dist-e2e`
и не попадает на GitHub Pages.

## GitHub Pages

Workflow `.github/workflows/ci.yml` проверяет форматирование, lint, типы, модульные
и компонентные тесты, собирает сайт и проверяет production сборку в Chrome.
После успешных проверок основной ветки сайт публикуется на
[GitHub Pages](https://gagarinbefree.github.io/TikWeather/).
Источником Pages настроен GitHub Actions.
Новый коммит отменяет предыдущий запуск для той же ветки.
Файл `.npmrc` закрепляет установку peer зависимостей Bootstrap при `npm ci`.
