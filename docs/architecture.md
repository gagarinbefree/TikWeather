# Архитектура

Приложение является статическим Vue SPA для GitHub Pages.
Один экран показывает одну вертикальную карточку на всю доступную высоту.
На широком экране область карточки располагается по центру и сохраняет портретные пропорции.

## Границы

- `app` создаёт Vue и Pinia и подключает общие стили.
- `pages/weather` собирает главный экран из нижних слоёв.
- `widgets/weather-grid` связывает движок TikiTaki с шаблонами Vue.
- `features/current-weather` управляет загрузкой A1, отменой и повтором.
- `features/forecast` загружает дневной и почасовой прогноз с приоритетом выбранного дня.
- `entities/location` получает координаты устройства и резерв GeoJS.
- `entities/weather` содержит чистую модель сетки и её реактивное хранилище.
- `shared` содержит независимые ресурсы, темы и общие компоненты.

Импорты других срезов используют публичный `index.ts` через псевдоним `@/`.
Код нижнего слоя не импортирует верхний. Тесты имеют доступ к публичным API всех слоёв.

`WeatherGrid` совместим с типом `Grid` пакета TikiTaki. Движок свайпов
подключён через опубликованный Vue адаптер и шаблонный `Teleport`.
Код библиотеки не копируется и не подключается по абсолютному пути.

## Жизненный цикл ячеек

`useWeatherSwipe` создаёт движок после монтирования экрана и уничтожает перед
размонтированием. Движок владеет контейнерами текущей ячейки и соседей,
Vue владеет их содержимым через `Teleport`. Слоты сохраняют контекст Vue,
инъекции и доступ к Pinia. Неактивные контейнеры скрыты от экранного диктора
и исключены из фокусировки средствами TikiTaki.

Обновление сетки проходит после обновления Vue. Выбранная ячейка ищется по
стабильному идентификатору, поэтому добавление или удаление предыдущей строки
не меняет её смысл. Если ячейка исчезла, движок ограничивает позицию доступной
сеткой. Номер обновления исключает публикацию устаревшего результата перехода.

Стрелки клавиатуры работают при фокусе на области прогноза и не перехватываются
у вложенных кнопок. Уменьшение движения учитывается при создании движка.
Сбой движка освобождает ресурсы и показывает локализованное сообщение.

## Модель сетки

`createWeatherGrid` получает фиксированное время, часовой пояс местоположения
и список доступных дней с реальными часовыми метками. Результат содержит
неизменяемые описатели текущей погоды, дневной сводки и часового прогноза.

Первый снимок содержит только текущую ячейку. После её загрузки отдельный
планировщик создаёт пустые слоты максимум для 16 местных дней.
Слоты не содержат выдуманных погодных значений: до ответа API карточка показывает спиннер.
Дни без часов остаются строками из одной сводки.
Идентификаторы зависят от местной даты, вида ячейки и абсолютной временной метки.

Даты вычисляются через `Intl.DateTimeFormat` с явно переданным часовым поясом.
Разбор строк дат через системную культуру не используется.
Границы суток, пропущенные и повторившиеся часы учитываются по реальным меткам API.

Число строк определяется входными данными. После длинного запроса планировщик
удаляет слоты за пределами фактически полученного прогноза.

`useWeatherGridStore` атомарно заменяет корректный снимок. Некорректное обновление
сохраняет предыдущий снимок. Начальный UTC является техническим значением до
подключения геолокации. После текущей погоды сетка пересоздаётся с часовым поясом
ответившего источника.

## Загрузка текущей погоды

`app/main.ts` создаёт зависимости и передаёт их через типизированный ключ Vue.
Pinia хранит состояние загрузки, язык и валидированные наблюдения. Сетевые функции
получают `AbortSignal` и возвращают модели без зависимости от компонентов.
Текущая погода не зависит от готовности прогноза.

Геолокация ограничена внешним таймером, потому что браузер может оставить запрос
разрешения открытым. Поздний ответ не меняет уже выбранный резерв. GeoJS используется
только после недоступности геопозиции. Если оба способа не сработали, WeatherAPI
сам определяет IP через `auto:ip`.

`shared/api` ограничивает как получение ответа, так и чтение тела, различает отмену,
таймаут, сетевой сбой, отказ доступа и некорректные данные. Сообщения исключений
содержат только безопасные коды, без ключа, URL и ответа поставщика.
Запросы являются обычными GET без нестандартных заголовков и cookies.
Браузер управляет CORS, переключение системного и прямого маршрутов .NET не переносится.

Время WeatherAPI используется из Unix epoch и форматируется с явным IANA поясом.
Ответ проверяется до публикации состояния. Номер запроса и отмена исключают
замену свежей карточки результатом старого запроса после повтора или закрытия.

## Загрузка прогноза

Запрос `forecast.json` получает часовые значения, дневную сводку и время восхода
и заката. Ответ проверяется до публикации. Хранилище прогноза начинает с запроса
на один день, затем расширяет горизонт до трёх и полного доступного числа дней.
Выбор ещё не загруженной строки отменяет меньший запрос. Номер запроса
исключает применение запоздалого ответа после перехода, повтора или закрытия.
Успешно загруженные дни остаются видны при последующей сетевой ошибке.
Каждый успешный ответ обновляет часы сетки фактическими метками своего поставщика.
Для ещё не загруженных дней сохраняются пустые слоты. Это исключает карточки,
привязанные к часам предыдущего поставщика после переключения резерва.

Текущие данные и первые дни прогноза независимо проходят цепочку WeatherAPI,
Open Meteo, OpenWeatherMap. Следующий источник вызывается после ошибки предыдущего.
Длинный запрос проверяет Open Meteo (до 16 дней), WeatherAPI (до 14 дней) и
OpenWeatherMap и объединяет ответы по местной дате: новые дни добавляются, а для
пересекающихся дат остаются более подробные почасовые данные. Интервал выбирается
для каждого дня отдельно. Успешно завершённый длинный запрос не повторяется
при каждом переходе между его днями. Отмена прерывает запросы.
Если ни один источник не ответил, интерфейс показывает тип первой ошибки.

Open Meteo принимает координаты и возвращает часовые данные с Unix метками времени.
OpenWeatherMap запрашивает текущие измерения и прогноз с шагом три часа.
Адаптер группирует реальные метки по календарным дням местоположения и возвращает
все доступные дневные сводки одним запросом прогноза. Часовой пояс текущей погоды определяется
по координатам локально. Отсутствующие у поставщика показатели остаются `null`
или `undefined` и отображаются как «Нет данных».

## Ресурсы

Подключены русские и английские строки, описания погоды, ошибки и единицы.
Язык выбирается по стране, до ответа используется язык браузера.
Карточки текущей погоды и прогноза используют четыре начертания Inter,
Fluent SVG и именованные пастельные цвета AvaWeather. Текущая карточка
получает поверхность `Current`, а дневная и почасовая — поверхность `Forecast`
для соответствующего погодного условия. Значок сайта использует графику приложения.
Единственный источник цветов находится в `shared/assets/themes/default.json`.
Каталог `shared/assets/weather/conditions.json` связывает коды иконок с темой через данные.
Тексты условий WeatherAPI находятся в отдельных ресурсах и не требуют второго запроса.
Локализация названий мест остаётся следующим этапом.

Bootstrap подключается через Sass `@use`. Импортируются только корневые стили,
сброс оформления, спиннер, кнопка и вспомогательные стили скрытого доступного текста.
JavaScript плагины Bootstrap стартовому экрану не нужны.

Weather provider access now uses the shared VPS without client credentials. See [backend transport](backend.md).
