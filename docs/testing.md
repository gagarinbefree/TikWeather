# Тестирование

## Расположение

Все тесты находятся в `src/tests`. Внутри повторяется структура приложения.
Тест `src/entities/weather/model/create-weather-grid.ts` находится в
`src/tests/entities/weather/model/create-weather-grid.test.ts`.

- `*.test.ts` запускаются Vitest.
- `*.e2e.ts` запускаются Playwright.

Конфигурационные файлы тестовых инструментов находятся в корне проекта.
Исходные файлы приложения не содержат размещённых рядом тестов.

## TDD

Для первого этапа тесты сетки, Pinia и страницы были созданы до реализации.
Первый прогон зафиксировал ошибки отсутствующих модулей. После реализации
повторный прогон проверяет поведение описанного публичного API.

Для новых возможностей соблюдается последовательность RED, GREEN, REFACTOR.
Тесты используют фиксированные время и часовой пояс и не обращаются к погодным API.

## Проверки

Модель проверяется на порядок строк и часов, двухчасовые интервалы,
трёхчасовую детализацию, отсутствие данных, сохранение идентификаторов,
местные сутки, переходы летнего времени, дубликаты и некорректный ввод.

Компонентные тесты проверяют семантический экран и доступный индикатор загрузки.
Playwright открывает production сборку по пути `/TikWeather/` в Google Chrome,
проверяет спиннер, отсутствие ошибок JavaScript и консоли и размеры карточки
на мобильном и широком экранах.

Полная команда `npm run check`. Перед первым браузерным прогоном нужен
`npx playwright install chrome`. В CI Chrome устанавливается вместе с
системными зависимостями. Отчёты и трассировки сохраняются при ошибках.

Физический Android и настоящие погодные API пока не проверялись и относятся
к следующим этапам.

## Проверка первого этапа

Модульные и компонентные тесты, строгая проверка типов, lint и production сборка
проверены локально. Прошёл 31 модульный и компонентный тест. В используемой ограниченной среде Windows запуск
дочерних процессов Playwright блокируется ошибкой `spawn EPERM`.
Это ограничение среды, а не успешный прогон браузерных тестов.
Оба общих сценария Playwright успешно выполнены через подключённый Chrome
для мобильного и широкого экранов, всего четыре проверки.
Полный прогон стандартного runner предусмотрен в GitHub Actions.

## Подключённый Chrome

Если Chrome уже запущен с разрешённым отладочным подключением, можно выполнить
те же assertions через CDP без запуска нового браузера и дочерних процессов runner.
Сначала запустите production сервер командой `npm run preview -- --port 4173`.
Затем укажите фактический адрес отладочного подключения и запустите проверки.

```powershell
$env:PLAYWRIGHT_CDP_URL = 'http://127.0.0.1:9222'
npm run test:e2e:connected
```

Сценарии используются совместно со стандартными `*.e2e.ts` тестами.
Проверки создают и закрывают собственные изолированные контексты.
Они не используют вкладки и пользовательские данные существующего браузера.
